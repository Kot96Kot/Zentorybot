# Модуль «План продаж»

Модуль «План продаж» помогает менеджеру маркетплейсов контролировать выполнение плана по каждому SKU и быстро видеть, где нужны действия: закупка, корректировка рекламы, анализ карточки или пересмотр дневного фокуса.

## Цель

Считать план продаж на день, неделю и месяц, сравнивать факт с планом и формировать mock-алерты для Telegram. Реальные API WB, Ozon и Яндекс Маркета не подключаются.

## Telegram-команды

- `/sales_plan` — построить mock-план продаж по всем SKU.
- `/sales_plan_sku <sku>` — построить mock-план по конкретному SKU.

Пример:

```text
/sales_plan_sku ZNT-OZON-002
```

## Входные данные

- `sku` — внутренний SKU.
- `marketplace_articles` — артикулы WB/Ozon/Яндекс Маркет.
- `current_sales` — факт продаж за текущий день.
- `sales_7d`, `sales_14d`, `sales_30d` — продажи за 7/14/30 дней.
- `stock` — текущий остаток.
- `average_price` — средняя цена.
- `target_revenue` — целевая выручка.
- `target_margin` — целевая маржа.
- `ad_spend` — рекламные расходы.
- `impressions` — показы.
- `seasonal_coefficient` — сезонный коэффициент.
- `drr_limit` — лимит ДРР.

## Выходные данные

- план продаж на день;
- план продаж на неделю;
- план продаж на месяц;
- факт;
- отклонение в процентах;
- статус: `ok`, `warning`, `critical`;
- рекомендации;
- alerts;
- tasks;
- mock-флаг.

## Правила статусов

| Условие | Статус | Действие |
|---|---|---|
| Факт ниже плана больше чем на 15% | `warning` | Проверить трафик и конверсию |
| Факт ниже плана больше чем на 30% | `critical` | Поднять приоритет SKU |
| Остатка меньше чем на 14 дней | alert | Создать alert по закупке или подсорту |
| ДРР выше лимита | alert | Проверить рекламные ставки и кампании |
| Заказов нет, но показы есть | task | Создать задачу на анализ карточки |

## Как считается план

Дневной план берется как максимум из двух значений:

1. План по целевой выручке: `target_revenue / average_price / 30`.
2. Исторический план: максимум среднедневных продаж за 7/14/30 дней, умноженный на сезонный коэффициент.

Недельный план = дневной план × 7. Месячный план = дневной план × 30.

## Безопасность

Модуль только создает mock-отчеты, alerts и proposed actions. Он не меняет цены, рекламные ставки, карточки и поставки. Любое будущее write-действие должно проходить через Decision Engine, approval, audit log, idempotency и safe mode.
