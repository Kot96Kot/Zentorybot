# Модуль генерации контента карточки товара

Модуль помогает менеджеру маркетплейсов быстро собрать draft карточки по минимальным вводным. На этапе scaffold используется mock LLM provider: реальные OpenAI, Anthropic или другие LLM API не вызываются.

## Цель

По короткому брифу сформировать структуру карточки:

- SEO-название;
- описание;
- УТП;
- преимущества;
- характеристики;
- ТЗ на инфографику;
- ТЗ на фото;
- ТЗ на видео;
- список ключевых слов;
- чеклист перед публикацией.

## Telegram-команды

- `/content_new` — создать draft по mock-брифу или названию товара.
- `/content_new вакууматор для продуктов` — создать draft для указанного товара.
- `/content_sku <sku>` — создать draft для SKU из mock-данных.
- `/content_brief` — обработать структурированный brief из payload webhook.

## Архитектура

- `ContentAgent` принимает событие Telegram/API и формирует actions.
- `ContentGenerationService` строит бриф и вызывает LLM provider.
- `ContentLLMProvider` — абстрактный контракт будущей LLM-интеграции.
- `MockContentLLMProvider` — текущая реализация без внешних API.
- `ContentCardDraft` — Pydantic-схема draft-карточки.

## Draft mode и approval

Контент всегда создается в режиме `draft`. Система не публикует изменения автоматически. Для любого применения контента создается action `content_apply_requires_approval` с высоким риском, чтобы Decision Engine назначил жесткое подтверждение.

## Минимальные вводные

- marketplace;
- категория;
- название товара;
- бренд;
- артикул;
- цена;
- основные характеристики;
- боли покупателя;
- конкуренты;
- ограничения площадки.

## Безопасность

- Реальные LLM API не подключены.
- Все результаты помечаются `mock: true`.
- Любая будущая публикация должна идти через safe mode, approval, audit log и idempotency.
- Ограничения площадки передаются в prompt и checklist.
